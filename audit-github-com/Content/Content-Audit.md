# Content / Copy Audit

**Score: 83/100.** The in-product voice is unusually clear and trustworthy. The primary content gap is public narrative/discoverability, not grammar.

## Observations
- README and release notes state limitations clearly: no live testing, no autonomous submissions, no fake data, no guaranteed rewards. Good.
- Docs have depth: Windows Setup, Operations, Verification, Sources, Restore, Implementation Plan; community/security files are present.
- UI page headings and empty-state messages are action-oriented and honest.
- Missing public landing, FAQ, support/contact path, accessibility statement, privacy/terms explanation, searchable docs, demo walkthrough.
- README could improve first-time scanning with badges, TOC, screenshots/GIF, “for/not for”, concise troubleshooting and release checksum links.

## Editorial guardrails
- Never claim autonomous penetration testing or guaranteed bounty earnings.
- Distinguish actual results from estimates; keep awards/payments as real-only.
- Label Windows/Docker verification status precisely.
- Avoid “AI-powered” as a vague headline; explain deterministic intent routing + optional local model.
- Keep UK English (`programme`, `authorisation`), plain language, concise headings.
